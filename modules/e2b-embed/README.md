# E2B Embed

Import this module only in hosts that use it:

```nix
imports = [ ../../modules/e2b-embed ];
local.e2b-embed.enable = true;
```

Alternatively import it in a shared module list and enable it per host. With
`enable = false` (the default), it creates no users, units or kernel settings.
The redtail configuration enables it. Defaults: 6 vCPUs, 12288 MiB memory,
80 GiB sparse disk; options live under `local.e2b-embed`.

## Why a VM

[Upstream requirements](https://github.com/e2b-dev/runtime/blob/main/embed/compose/README.md#requirements)
include KVM, cgroup v2, kernel 6.8+, rootful Docker 27+, Compose 2.24+, 12 GiB
RAM recommended and 20 GiB free disk. Its privileged setup and orchestrator
enter PID 1's namespaces and execute against Ubuntu paths. A dedicated Ubuntu
24.04 guest preserves upstream Compose dependency/healthcheck behavior and
keeps host filesystem, hugepage and firewall mutations inside that guest.
No Docker daemon or docker group is needed on NixOS.

The host needs working KVM with nested virtualization. The module configures
Intel and AMD nested KVM options. If KVM is already loaded without nesting,
a reboot may be necessary; do not unload KVM while other VMs are running.
This module currently supports x86_64 hosts only.

## Start and access

After building and switching the NixOS configuration:

```sh
systemctl status e2b-embed e2b-embed-proxy
journalctl -u e2b-embed -f
e2b-embed-ssh 'sudo journalctl -u e2b-embed -f'
```

`e2b-embed-ssh` uses sudo to run SSH as the VM service account. No passwordless
sudo rule is installed. The VM generates an SSH key at runtime, outside the Nix
store. Guest Ubuntu's default cloud user has sudo access through that key.
The helper accepts normal SSH arguments; use `e2b-embed-ssh -t` for a terminal.

The VM unit being active means QEMU is running, not that E2B is ready. First
boot installs Docker from its signed repository, fetches the pinned Compose
pair, downloads images and builds the base template. Allow several minutes.
The guest service retries failed bootstrap attempts every minute.

```sh
e2b-embed-ssh 'sudo docker compose --project-directory /opt/e2b ps'
e2b-embed-ssh 'sudo docker compose --project-directory /opt/e2b exec -T ready cat /run/e2b/sdk.env'
e2b-embed-ssh 'sudo docker compose --project-directory /opt/e2b --profile test run --rm smoke'
```

The second command prints credentials: keep its output private. The final command
is the upstream end-to-end smoke test: create a sandbox, execute a command,
reach an exposed port and kill the sandbox. Run this before treating deployment
as complete. Credentials are generated by upstream and persist in guest volumes.

Dashboard: http://localhost:3001 ; API: http://localhost:3000 ; sandbox proxy:
http://localhost:3002 . Port 5008 is also forwarded to localhost for template
uploads. SSH is on localhost:2222. By default no firewall ports are opened. Database and
other control ports remain inside the guest. Existing listeners on those host
ports must be stopped or the tunnel will fail clearly in its journal.

For LAN access, configure this on the selected host:

```nix
local.e2b-embed.lan = {
  enable = true;
  address = "10.11.196.5";
  subnet = "10.11.196.0/24";
};
```

This adds listeners on the specified address for TCP 3000 (API), 3001
(dashboard) and 3002 (sandbox proxy), with firewall rules restricted to the
specified source subnet and destination address. Localhost access is retained.
The module supports the NixOS iptables and nftables firewall backends. SSH,
5008 and database/control services are not exposed to the LAN. Host SSH rules
are unchanged. Keep the LAN address stable with a DHCP reservation or static IP.

`e2b-embed-settings.service` waits for guest provisioning and updates
`E2B_DASHBOARD_HOST` in the guest `.env`, then reconciles only the dashboard.
It handles existing guests as well as first installations, without restarting
the orchestrator. It retries while the guest is starting. When LAN access is
disabled, it restores the dashboard sandbox address to localhost.

On this LAN, open http://10.11.196.5:3001 . Remote SDK clients should use
`E2B_API_URL=http://10.11.196.5:3000` and
`E2B_SANDBOX_URL=http://10.11.196.5:3002`, plus the existing API key. The
`ready` container's exported URLs still use localhost; override them for LAN
clients. Port 5008 is an internal unauthenticated control API, so template
uploads requiring it should still run locally or through an SSH tunnel.

## Persistence and maintenance

Guest state is under `/var/lib/e2b-embed/disk.qcow2`. Stop the VM before taking
a filesystem copy. Disable `local.e2b-embed.enable` to stop it and remove its
units while retaining data. Do not delete the state directory unless you intend
to erase the installation, templates, sandboxes and credentials.

`systemctl stop e2b-embed` sends ACPI shutdown and waits up to 150 seconds for
Ubuntu to stop Compose cleanly. Running sandboxes end. VM reboots run `compose up`
again to restore transient network and namespace setup. Container restart policies
handle ordinary container exits. The host proxy reconnects when SSH returns.

The Ubuntu image is fixed by SHA256 (published 20261017), even though the download
URL names `current`. If Ubuntu replaces that URL's content before the first
build, update `imageUrl` to an archive of that build or update `imageSha256` from
Ubuntu's published SHA256SUMS after reviewing the new image. A mismatch fails
closed. Changing either option never replaces an existing guest disk.

`runtimeRevision` pins the initial Compose download to commit `78d5ff9`.
Changing it or cloud-init settings does not reconfigure an existing guest:
cloud-init runs once and the bootstrap preserves downloaded files. For upgrades,
back up the guest, fetch **both** Compose files from a reviewed commit inside
`/opt/e2b`, preserve optional settings in `.env`, and run `compose up -d --wait`.
Upgrades can end running sandboxes. Ubuntu/Docker package updates are maintained
inside the guest, independently of the NixOS lockfile.

## Validation in this session

Nix evaluation and shell syntax checks can run without host mutation. The session
sandbox prevents Nix daemon access and shell network downloads, and `/dev/kvm`
is not visible. No guest has been booted or smoke-tested in this session.
